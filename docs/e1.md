# E1 — H1 on HumanEval + Controlled Context

**Article reference:** §7.2; tests hypothesis **H1** (token efficiency of
Hybrid-INoT vs Classical-MAS at long context).

## What we measure

For each architecture **CTRL NoAssistant**, **B0 SingleLarge**, **B1 SelfRefine**,
**B2 ClassicalMAS**, **B3 HybridINoT** and each context length
`|C0| ∈ {512, 2048, 8192}` (seeds: 42, 123, 456, 789, 1337):

- `pass@1` — fraction of tasks solved on first try (the article's `Q`).
- `T̄` — mean total tokens per task.
- `U_tok = pass@1 / (T̄ / 1000)` — formula (17).
- `Q$ = pass@1 / C̄_inf` — formula (18).
- `VCR` — verified candidate rate (formula (19)).
- `MAS_i` averaged across tasks (formula (20)).

## How we test H1

1. Build per-task arrays of `U_tok` for B2 and B3, aligned by `(task_id, seed)`.
2. Run paired **Wilcoxon signed-rank** between B3 and B2.
3. Bootstrap 95% percentile CI (10⁴ resamples) for the mean ΔU_tok.
4. **Holm–Bonferroni** correction across the three context-length subgroups.
5. Run **McNemar** on paired binary `pass@1` to monitor quality regression.

H1 is **CONFIRMED** at `|C0| = 8192` iff:
- `ΔU_tok / U_tok^{B2} ≥ 15%`,
- `pass@1` regression of B3 vs B2 ≤ 2 p.p.,
- Holm-corrected Wilcoxon p-value < 0.05.

## How to reproduce

```bash
# Smoke test (no API spending)
python -m inot check

# Full E1 against article spec (164 tasks × 3 ctxs × 5 seeds)
python -m inot e1 --n 164 --seeds "42,123,456,789,1337"

# Quick pilot (few tasks, 2 seeds)
python -m inot e1 --n 20 --seeds "42,123"

# HumanEval + custom controlled-context suite from the coursework text
python -m inot e1 --n 20 --seeds "42,123" --suite both

# Only the custom controlled suite, useful while tuning prompts
python -m inot e1 --n 20 --seeds "42,123" --suite controlled

# View results in a nice terminal panel after the run
python -m inot view e1
```

## Why this design

- The article's E1 protocol fixes "all factors except orchestration": same
  base model, same `K`, same `I`, same seeds, same prompts. We do exactly
  that — the only difference between architectures is how role calls are
  decomposed.
- HumanEval context ("legacy project history") is sampled from sibling
  HumanEval prompts and canonical solutions, never from the *target* task,
  so we cannot leak the answer.
- The controlled custom suite (`build_controlled_context_suite`) uses fixed
  task families and deterministic decoy repository context, so it isolates
  context length as the independent variable.
- `CTRL_NoAssistant` is included as the no-assistant control point from the
  coursework: zero LLM calls, zero token cost, starter scaffold only.
- Context lengths span the article's `{512, 2048, 8192}` band, which brackets
  the predicted `τ⋆`.
