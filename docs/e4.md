# E4 — Small-model self-check: hypothesis H2

**Article reference:** §7.5. Tests inequality (16):

> `C_check^S < (ρ0 − ρ1) · C_rerun^L`

## What the experiment does

For every task in the dataset we:

1. Run **B0 SingleLarge** with the *large* model. Record cost and verdict.
2. Send the candidate solution to the **small** model with a `PASS / REJECT`
   pre-screening prompt. Record its decision and cost.
3. Estimate:
   - `ρ0`     = `P(rerun needed | no small check)` ≈ `P(B0 fails)`
   - `ρ1`     = `P(rerun needed | small says PASS)` ≈ `P(B0 fails ∧ small=PASS)`
   - `C_check^S` = mean small-check cost in USD
   - `C_rerun^L` = mean B0 cost in USD (one rerun = one large call)

The per-task net margin is

    margin_i = saved$_i − check$_i
    saved$_i = (B0 fails ∧ small says REJECT) · large_cost_i

The mean margin is bootstrapped (10⁴ resamples) for a 95% CI. **H2 is
confirmed** on a dataset iff `lower CI > 0`. The article requires
confirmation on **both** HumanEval and SWE-bench Lite; if SWE-bench Lite is
unreachable we substitute the **Synthetic Tool-Use Suite** (a different
distribution still satisfying the "two datasets" requirement) and note this
in the verdict file.

## How to reproduce

```bash
# Article spec: 100 HumanEval + 50 SWE-bench Lite
python -m inot e4 --n 100 --seeds "42,123"

# Quick pilot
python -m inot e4 --n 20 --seeds "42"
python -m inot view e4
```

Outputs in `results/e4/{humaneval,swebench_lite|synthetic_tool_use_suite}/`:

- `runs_b0.json`
- `summary.json` — `ρ0, ρ1, C_check^S, C_rerun^L, margin, CI`
- `fig_h2_savings.png` — histogram of per-task net margins
- `H2_VERDICT.md` — combined cross-dataset decision

## Why this design

- The article's H2 is a **purely economic** claim: it has nothing to do with
  whether the small model is *good* at code review in absolute terms — only
  with the cost-weighted balance between cheap pre-screening and avoided
  expensive reruns. Our procedure measures exactly that quantity, in real
  USD, on real API calls.
- We bootstrap the *per-task* margin, not the difference of averages, so the
  CI captures task-level variability that the analytical inequality (16)
  hides under expectations.
